# 工商银行流水处理脚本

今后的标准流程固定为“PDF 转 Excel → 人工检查 Excel → 只读核对 → 审核调整清单 → 单独执行写入”。第一步生成的 Excel 是后续处理的唯一银行流水输入，原 PDF 仅用于提取和追溯。

## 1. PDF 转 Excel

```powershell
uv run --script scripts/icbc_pdf_to_excel.py "tmp/工商银行历史明细_000000.pdf"
```

默认输出与 PDF 同名的 `.xlsx` 文件。文件已存在时脚本会拒绝覆盖；确认需要重新生成后才使用 `--force`。PDF 密码优先从环境变量 `ICBC_PDF_PASSWORD` 读取，否则尝试使用文件名末尾六位数字。

Excel 包含：

- `转换说明`：来源文件、SHA-256、时区和处理约定。
- `工商银行流水`：原表 11 列、顺序号、PDF 页码和 PDF 行号，可筛选和排序。

转换完成后脚本会从 Excel 重新读取全部流水，并与 PDF 解析结果逐笔比较；任一字段不一致即失败。
工作簿不包含公式，因此无需依赖本机 Excel 或 LibreOffice 重算，也不会出现未刷新缓存值。

## 2. 一条命令完成转换和只读核对

```powershell
uv run --script scripts/icbc_workflow.py "tmp/工商银行历史明细_000000.pdf" `
  --username example-user `
  --account "工资卡" `
  --strict
```

该示例会在终端中安全提示输入密码。也可以在当前终端临时设置普通字符串环境变量 `EZBOOKKEEPING_PASSWORD`，运行结束后立即移除；不要把密码写进脚本、命令文件或配置文件。

该命令严格先生成 Excel，再把 Excel 路径交给只读核对脚本。未传 `--username` 时只执行 PDF 转 Excel。默认不会新增、修改或删除线上记录。

## 3. 单独使用 Excel 核对

```powershell
uv run --script scripts/icbc_reconcile.py "tmp/工商银行历史明细_000000.xlsx" `
  --username example-user `
  --account "工资卡" `
  --output "tmp/工商银行收支核对报告.md" `
  --strict
```

## 4. 固定核对规则

1. 时间按 UTC+8 精确到秒，金额使用有符号分金额。
2. 容差匹配仅限收支方向相同且在同一自然日；先比较时间相似度，再比较金额差。
3. 普通金额容差为 0.05 CNY；双方绝对金额均不超过 10.00 CNY 时允许金额不同并列出差异。
4. PDF 摘要“理财”和“金融付款”均视为转入支付宝基金，按银行具体日期汇总。
5. 银行侧等额、反向的转入转出按时间最接近原则一对一抵销，不计入未匹配统计。
6. 补录未匹配流水时：收入归“其他收入”；2.60–2.80 CNY 的支出归“公共交通”并备注地铁；其他支出归“其他支出”；银行摘要写入备注。
7. 任何线上调整必须先生成清单和备份、人工审核，再使用独立写入脚本显式执行；不得把写入开关加入默认工作流。

现有的受控调整脚本也接受转换后的 `.xlsx`，但其默认模式仍只生成清单和备份。只有人工审核清单后显式传入 `--apply` 才允许调用写接口。
